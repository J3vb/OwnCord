# Discord parity and debug sweep (2026-10)

**Date:** 2026-10-09
**Audited tree:** `dev` at `610ec96`
**Scope:** every user-facing area of the desktop client and the server
handlers behind it, compared with what a regular Discord user expects, plus a
pass over real bugs: the unit suites, lint and typecheck, the CHANGELOG "Known
issues", the findings ledger and the `TODO`/`FIXME` markers in hot paths.
**Method:** code reading against the behaviour specs in
`docs/architecture/ux/`, three parallel read-only code sweeps (messaging; DMs,
calls, voice and presence; channels, roles, moderation and settings), then a
second reading of every row marked "fix now" before it went into this table.
Nothing in this document was verified on a real desktop; "manual check" in a
fix PR is where that happens.

**Out of scope, handled elsewhere:** Linux GIF loading (CSP `ipc:`),
drag-and-drop file upload, the native-voice interop video test flake, the
Windows update smoke test, the Discord-style server rail / multi-server
sidebar, and the parity items already filed as P2–P5 (`channel_stale`,
presence and writer scaling, P4-04 and P4-15 protocol work, the P5 scale
items). Rows that only restate one of those are marked **skip** with the
reason.

## How to read the tables

| Column    | Meaning                                                                                                                                                                                                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Impact    | What a regular user notices: **high** (daily use, or data they lose or miss), **med** (a feature they reach for and find missing or wrong), **low** (polish).                                                                                                                                           |
| Effort    | **S** one file or one function and a test, **M** a few files on one side, **L** both sides, a protocol or schema change, or a new subsystem.                                                                                                                                                            |
| Verdict   | **fix now**: contained, S or M, no protocol, schema, permission or product change. **needs product decision**: changes protocol, schema, permission semantics or product behaviour beyond the finding, or is L. **skip**: already handled elsewhere, deliberate per the UX spec, or not worth its code. |
| Fix batch | `PR` marks the eight items fixed in this sweep's session. `next` marks "fix now" items left for the next batch.                                                                                                                                                                                         |

References are `file:line` at the audited tree. "Discord" means the free
tier's behaviour.
