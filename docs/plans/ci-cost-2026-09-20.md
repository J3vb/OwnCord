## What was changed

1. **Change-based selection.** A `changes` job classifies the PR diff and gates
   the nine heavy jobs. Hygiene and Docs & Ledger Consistency stay
   unconditional — they are cheap and they are what a prose change most needs.
2. **The plain admin leg.** It ran the whole `admin` package (62.6s) to reach one
   `!race && !deadlock` test (0.088s). `TestSetupLimiter_ReapsStaleEntries` is
   60.00s of that package and is _untagged_, so the two universal legs already
   run it — the plain leg was paying a minute of critical path to repeat a test
   it had already run twice.
3. **The browser jobs.** `client-e2e` and `client-e2e-parity` ran the _same_ 292
   tests: `playwright.config.prod.ts` inherits `testDir` and `testIgnore` from
   the base config, so `--list` reports 292 tests in 41 files for both. The
   production run stays complete; the dev run became a 92-test smoke set, and
   the mocked configs were widened to two workers.

## The dependencies the selection rules had to encode

A path-prefix rule gets this wrong, because components read files outside
themselves. Each of these is a real read in the tree:

| File read                                 | By                                                             |
| ----------------------------------------- | -------------------------------------------------------------- |
| `docs/schema.md`                          | `permissions/schema_doc_test.go`                               |
| `docs/api.md`                             | `make docs-verify`, `tests/contract/api-profile-route.test.ts` |
| `docs/architecture/server-boundaries.md`  | `cmd/dbinventory/doc_test.go`                                  |
| `docs/architecture/community-services.md` | `migrations/community_services_doc_test.go`                    |
| `Client/src/lib/types.ts`                 | `permissions/schema_doc_test.go`                               |
| `Server/admin/static/index.html`          | five `tests/contract` specs                                    |
| `.superpowers/findings-ledger.json`       | `cmd/smoke/drills.go`                                          |

The two architecture documents are the trap worth naming: they are Markdown, so
a "docs are prose" rule skips them, and the Go tests that read them run with
`-count=1` precisely because Go's test cache cannot see an input outside the
module.

## What was deliberately not done

- **Sharding the `-race` leg**, the largest remaining item at 16.45m of a 24.5m
  critical path. Sharding requires merging per-shard coverage profiles before
  the required coverage floor is read, which means promoting
  `golang.org/x/tools` to a direct dependency and changing how a required gate
  computes its number. That is not a change to make without being able to run it
  repeatedly.
- **The Go build cache is cold on every run.** `Server Build & Test
(ubuntu-latest)` logs `Cache is not found`, while the jobs that declare
  `setup-go` race to save its key — and because a cache key is immutable and
  first-save wins, the job that finishes first publishes the cache every later
  run restores. The key contains the runner platform
  (`setup-go-Linux-x64-ubuntu24-…`, `setup-go-Windows-x64-…`), so this is two
  races rather than one, and the loser is always the leg that needs it most:

  | Platform | Instances                                            | Winner                  | Losers                                                 |
  | -------- | ---------------------------------------------------- | ----------------------- | ------------------------------------------------------ |
  | Linux    | `server-build-test`, `admin-e2e`, `client-fullstack` | `admin-e2e` (1.9m)      | `server-build-test` (24.5m), `client-fullstack` (5.7m) |
  | Windows  | `server-build-test`, `client-native`                 | `client-native` (18.9m) | `server-build-test` (20.0m)                            |

  Cache scoping compounds it: a cache is visible only to its own branch and the
  repository's default branch, which is `main` — and this repository's PRs
  target `dev`.

- **Moving any suite to nightly.** `nightly-test-depth.yml` exists on `dev` but
  not on `main`, and schedules fire only from the default branch: GitHub returns
  `HTTP 404: workflow nightly-test-depth.yml not found on the default branch`.
  It has never run.
