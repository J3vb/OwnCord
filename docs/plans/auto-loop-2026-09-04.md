# Auto-loop — unattended overnight PR pipeline

**Status:** IMPLEMENTED 2026-09-04 — `scripts/auto/`, 12/12 self-tests green
**Owner decisions:** all recorded below under _Decisions_

An orchestration layer that runs OwnCord's roadmap unattended overnight. A
plain bash loop polls GitHub every five minutes and launches short-lived
`claude -p` sessions when — and only when — something actually needs doing.
The loop itself consumes no model tokens.

## Why this shape

Three properties drove every choice:

- **GitHub is the state store.** PR status, CI results, review threads and
  labels already encode everything a worker needs. A parallel local database
  would be a second, staler copy.
- **Workers are disposable.** Every worker is a fresh `claude -p` with an
  empty context, scoped to one PR or one roadmap task. Nothing is resumed,
  so nothing accumulates confusion.
- **The model never merges.** `gh pr merge` is called by the shell. No prompt
  injection, no model error, and no runaway loop can reach that button.

## Decisions

| Question             | Decision                                                                |
| -------------------- | ----------------------------------------------------------------------- |
| Merge automatically? | Yes, squash into `dev` only. `main` is refused.                         |
| Merge gate           | CI green, no live review thread, no conflict, 15 min since the push     |
| Work queue           | `docs/plans/` roadmap, selected by a one-line cursor file               |
| Models               | Opus for coder and fixer, Sonnet for reviewer                           |
| Alerts               | `STUCK.md` on disk. No push notifications.                              |
| Budget               | Max subscription, not API credits — guard is session count, not dollars |
| Run window           | 22:00–09:00 local                                                       |
| Session cap          | 50 per night                                                            |
| PR scope             | Branches prefixed `auto/` **and** authored by the signed-in account     |
| Concurrency          | 3 workers; **but at most one coder task in flight**                     |

## Layout

Tracked:

```
scripts/auto/
├── auto.cmd            double-click launcher (accepts --dry-run)
├── loop.sh             the orchestrator
├── selftest.sh         the classifier's decision table, stubbed and asserted
├── README.md           start / stop / steer
└── prompts/
    ├── rules.md        the hard rules, prepended to every role
    ├── coder.md
    ├── fixer.md
    └── reviewer.md
```

Untracked runtime state — already covered by the existing `.claude/*` rule in
`.gitignore`, so no ignore changes are needed:

```
.claude/auto/
├── cursor              one line, e.g. "B5-PLAN"; the human steering wheel
├── STOP                presence of this file halts the loop
├── STUCK.md            what the loop gave up on
├── journal.md          plain-English event log
├── locks/              one directory per in-flight PR (mkdir is atomic)
├── attempts/           fix counts and already-retried run IDs
└── logs/               full transcript per worker
```

Worker scratch space lives in `.claude/worktrees/auto-*`, created with plain
`git worktree add` and removed when the PR merges. Claude's own `--worktree`
flag is not used: it always creates a new branch, and the fixer and reviewer
must land on the pull request's existing one.

## The tick

Every 300 seconds:

1. Exit if `.claude/auto/STOP` exists.
2. Sleep if outside the run window.
3. Stop if the night's session count has reached 50.
4. Prune worktrees and locks whose PR has closed.
5. Fetch open PRs from `gh`. Consider only those whose base is `dev` and whose
   head branch starts with `auto/` **and whose author is the signed-in
   account**. If that call fails, the tick is skipped rather than treated as
   an empty queue — an empty list and a failed list are indistinguishable, and
   guessing "empty" would start a second coder on top of a live one.
6. Handle each PR in a subshell, so one failure cannot kill the loop.
7. If no `auto/` PR is open at all, start a coder.

### Per-PR classification

Evaluated in order; the first match wins.

| Condition                                                | Action                                                             | Model  |
| -------------------------------------------------------- | ------------------------------------------------------------------ | ------ |
| Fix attempts ≥ 3 and still not green                     | label `auto: stuck`, append to `STUCK.md`, never revisit           | —      |
| CI failed and this failure has not been retried          | `gh run rerun --failed`                                            | —      |
| CI failed after a retry                                  | fixer                                                              | opus   |
| A review thread that is unresolved and not outdated      | fixer                                                              | opus   |
| Draft, no worker holds the lock, unchanged for two ticks | coder (resumes the abandoned task)                                 | opus   |
| Green, never reviewed                                    | reviewer — comments only, never approves                           | sonnet |
| Green, no live thread, no conflict, push has settled     | **shell merges**: squash into `dev`, delete branch, advance cursor | —      |
| Anything else (CI pending, worker holds the lock)        | skip                                                               | —      |

The retry-before-fixer rule exists because this repository's most frequent CI
failures are environmental, not code: the Windows `-race` Go runtime fault,
the golangci-lint schema fetch, and the apt-mirror hang. Waking an Opus for
those wastes a session and changes nothing.

Both counters live in `.claude/auto/attempts/<pr>` — the number of fixer runs,
and the run IDs already retried. They reset when the loop restarts, which is
intended: a new night earns a fresh attempt. The durable record of an
abandoned PR is the `auto: stuck` label on GitHub, not the local counter.

A thread blocks the merge only when it is **unresolved and not outdated**.
GitHub marks a thread outdated once the code beneath it changes, so a fixer
that actually edits the flagged lines clears the block without anyone
clicking "resolve" — while a thread the fixer ignored stays live and keeps
blocking. Requiring a human click would stall every merge; letting the fixer
resolve its own threads would be self-approval by another name. Outdatedness
is the one signal that is neither.

## Workers

Each worker runs `claude -p` inside its own worktree, with a model and a
prompt built from `prompts/rules.md` plus its role file. Permissions are
bypassed — nothing is awake to answer a prompt. Isolation comes from the
worktree; `main` and force-push are refused by the prompt, by the merge
function, and by branch protection.

### Coder

Reads `cursor`, locates that task in `docs/plans/`, and implements it.

**Opens a draft PR on its first commit**, then keeps a `## Progress` block in
the PR description current: what is done, what is next, what was decided, what
was tried and rejected. That block is the handoff record. It is visible from a
phone, survives the session's death, and disappears when the PR merges —
which is why there is no separate local log. A successor coder reads it with
`gh pr view`.

Marks the PR ready for review only after `ci-check` passes.

**One coder task at a time.** Roadmap tasks share schema and audit contracts;
the roadmap itself serializes several B5 workstreams. Parallel coders would
produce colliding migrations.

### Fixer

Reads the PR, the failing job logs, and every unresolved thread. Fixes,
replies to each thread stating what it changed, runs `ci-check`, pushes.

### Reviewer

Reads the diff and posts review comments. **Never approves.** Codex already
reviews every PR here, and the merge gate requires resolved threads — so the
existing reviewer stays the real gate rather than the loop approving its own
work.

## Prompt rules every worker carries

1. Never hand-edit generated code. Use the `db-change` and `protocol-change`
   skills. B5 adds tables and WebSocket messages; a direct edit to `dbgen/` or
   `message_types.go` fails CI on drift.
2. Verify with the `ci-check` skill, never `go build && go test`.
3. This repository is public. Unfixed defects must not appear in commits,
   issues, or PR descriptions — security issues go through advisories.
4. A phantom conflict against `dev` is resolved with a merge commit, not a
   squash.
5. Conventional commit subjects; squash merges.

## Failure handling

| Failure                                 | Response                                                 |
| --------------------------------------- | -------------------------------------------------------- |
| A PR cannot be made green in 3 attempts | labelled `auto: stuck`, recorded, abandoned              |
| Usage limit reached                     | parse the reset time, sleep until then                   |
| 5 consecutive worker failures           | stop the night and record why                            |
| A single PR raises an error             | contained by its subshell; the loop continues            |
| Loop killed or window closed            | nothing is lost — GitHub and the draft PR hold all state |

## Starting state

`docs/plans/` has plan documents for B0 through B4 but **none for B5**; the
roadmap carries only a short sketch. The first cursor value is therefore
`B5-PLAN`, and the first task is to write the B5 plan document as its own PR,

## Verification

`bash scripts/auto/selftest.sh` drives `handle_pr` through every branch of the
decision table with the network, git and the model stubbed out, and asserts
which action each state selects — including the two merge refusals. It needs
no credentials and finishes instantly. Run it after editing `loop.sh`.

`auto.cmd --dry-run` performs a real tick against live GitHub —
classification included — and prints the actions it would take without
launching a worker, creating a worktree, or merging anything. Run it once
before the first unattended night.

`loop.sh` is covered by the repository's existing `shellcheck` gate through
`npm run check:hygiene`, which takes its file list from `git ls-files "*.sh"`.

## Deliberately excluded

- Filing reviewer findings into `.superpowers/findings-ledger.json`
- Handling Dependabot PRs, which have known target-branch quirks
- A Windows scheduled task; the first nights should be watched in a window
- Any dashboard beyond `journal.md`
